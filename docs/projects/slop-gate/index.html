Slop Gate
review the change, not just the line.

A deterministic CI gate for Rust pull requests that are getting larger, more complex, or suspiciously similar to code already in the repository.

Code review needs a baseline.

Formatting, compiler diagnostics, and dependency advisories each answer an important question. They do not tell a reviewer whether a pull request adds disproportionate function complexity, recreates an existing implementation, or expands the project’s unsafe and dependency surface.

Review in repository context

Slop Gate builds a versioned baseline artifact from a trusted Git commit, then evaluates only changed Rust functions in the candidate commit. Analysis runs locally, requires no model, and makes no network request while it is running.

What it measures

  • Function mass from cyclomatic complexity and source lines of code
  • Near-clones using normalized token and AST-shingle similarity
  • New or broadened compiler and Clippy diagnostic suppressions
  • Growth in unsafe blocks, declarations, implementations, and extern blocks
  • Production dependency and feature-surface changes
  • Concentration of complexity in high-complexity functions

Useful in agentic workflows

An agent can run Slop Gate against the change it has just made, giving the workflow a deterministic repository-level feedback loop before review or merge. That can catch complexity growth, duplication, or weakened diagnostics introduced by generated changes without asking another model to judge them.

Designed to complement Cargo tooling

Slop Gate complements cargo fmt, Clippy, and cargo audit. It emits human-readable output, JSON, or SARIF for CI systems. It does not prove semantic equivalence, assess security, or replace a linter.

Start conservatively

The default policy reports warnings rather than failing a build. Teams can calibrate thresholds against their own repository, promote specific rules to errors, and record narrow, reasoned suppressions when an exception is intentional.
