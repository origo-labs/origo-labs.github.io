Your application already knows the possible actions.

Many agentic workflows do not need another generative paragraph. They need to choose a tool, route a ticket, select a queue, or take the next branch in a defined process.

ZEV scores supplied candidates against shared context in one non-autoregressive pass. Candidate order does not define the score. Your application keeps control of permissions, policy, execution, and escalation.

A model for the decision step

context + candidates → ZEV scores → application policy → execute / escalate

ZEV is the decision model, not the whole agent. Planning, generation, tool execution, and permission checks remain in the system around it.

Built for bounded choices

  • Tool and action routing
  • Support and incident queue selection
  • Workflow branch selection
  • Local inference on customer infrastructure
  • Rust/Candle and PyTorch implementations

Evidence before integration

The public ZEV site reports 86.5% BFCL v3 agent-routing performance, 75.5% Banking77 top-3 performance, and sub-15ms CPU latency. These are public benchmark claims with workload-specific conditions, not universal deployment guarantees.

Evaluate the model against representative examples, acceptable errors, deployment constraints, and the hardware that matters to your system.

Closed-weight, licensed deployment

ZEV is an Origo Labs product with closed weights. Licensing, deployment options, evaluation, evidence, and the forthcoming hosted API are documented on the ZEV product site.

Where System-1 Gateway fits

System-1 Gateway provides the surrounding application boundary: typed interpretation, policy thresholds, abstention, routing, idempotency, and safe adapters. ZEV can supply the bounded decision model inside that larger pattern.
