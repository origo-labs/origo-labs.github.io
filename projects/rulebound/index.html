The premise

A rule in prose has no mechanism.

Agents can make a change that is locally plausible and globally wrong. Rulebound gives a repository a place to declare its quality contract, then runs that contract around an agent's work. The result is an explicit verdict, not a vague green tick.

Four outcomes, not one

Every run ends in a state the workflow can handle: accept when the contract passes, block when a declared rule fails, error when a gate could not produce a trustworthy result, or escalate when the contract reaches a boundary that needs human judgment.

contract → observe → gates → accept / block / error / escalate

Deterministic by default

Rulebound runs locally, makes no network request during analysis, and keeps the gate loop free of a model. It can emit human, JSON, or SARIF findings for local review and CI. That makes the checks inspectable; it does not make them omniscient.

The contract owns the boundary

The useful feature is the explicit limit. A repository can declare checks for tests, formatting, clippy, diff shape, dependency policy, or a project-specific invariant. When a claim cannot be expressed as a deterministic gate, Rulebound records that gap instead of pretending it has been proved.

Generalized from Slop Gate

Slop Gate reviews Rust pull requests for codebase-health changes such as function growth, near-clones, unsafe surface, and dependency expansion. Rulebound takes the same discipline and moves the contract to the project: the repository decides what “good” means, and the supervisor reports what happened.

What is measured

The current evidence covers 240 merges across nine repositories, with 29 graded states across two projects. In a small holdout set, deterministic gates caught all four seeded violations and stayed quiet on empty-diff states. The author also reports zero blocking-severity false positives in the merge corpus.

These are early, self-authored measurements. The evaluator wrote the gates and judged the findings; no independent validation has been performed.

What remains open

Rulebound is beta software. Ten of twelve gates currently run; secret_absent and judged report as unavailable rather than passing. Public API additions can be noisy, and checks_green has not been measured on large workspaces. The next work is broader fixtures, independent review, and clearer project-specific contracts.
