The tool call is often a finite decision.

System-1 Gateway turns a message, ticket, alert, or command into intent, entities, route, approval state, and confidence. GLiNER2.5 or GLiNER2.5-Decide performs the local semantic step; deterministic, typed policy code controls thresholds, abstention, routing, idempotency, and effects.

message → intent + entities → policy check → route or action

Interpretation does not grant authority

A model result can be accepted, abstained, or escalated. A separate auto_executable decision permits only explicitly allowed, low-risk routes. The bundled adapter is dry-run and suppresses duplicate idempotency keys; external action adapters remain an integration choice.

Configured around the actual decision

Domain packs define intent descriptions, routes, approval requirements, confidence thresholds, entity patterns, and optional typed decision tasks. The gateway provides CLI, JSONL-stream, and local HTTP interfaces, plus readiness, provenance, latency, throughput, abstention, and calibration reporting.

Built on Fastino’s open work

The gateway builds on Fastino’s GLiNER2.5 architecture and GLiNER2.5-Decide, an open-weight Apache 2.0 model for schema-defined decisions. Their release announcement describes the decision-model foundation; this project adds the application boundary around it.

Recorded fixture evidence

The repository reports 100% Choice accuracy, 83.3% Score accuracy, and 31.36 ms p99 latency on its recorded Apple Silicon fixture run. These figures apply to that implementation and fixture set. They do not establish deployment quality or accuracy for a customer workflow.
